# TFS Same-Day Cutoff

One Shopify Function that hides the same-day shipping rate once the store's
local clock passes 10:00.

## Why this exists rather than a scheduled job

Shopify shipping rates carry no time condition, so the obvious approach is a
cron that switches the rate off each morning. That was tried on paper and
rejected: GitHub Actions' scheduled runs are documented as not guaranteed, and
in practice have been running hours late and occasionally not at all. A cutoff
that fires at 14:00 is worse than no cutoff, because the AED 25 has already
been charged.

A function has no such problem. `shop.localTime` is evaluated inside Shopify,
against the **store's** timezone, and arrives as a boolean. There is no clock
to drift and no UTC offset to get wrong — which is also the thing to verify
first in any paid app that claims to do this.

## What it does

Target `cart.delivery-options.transform.run`. After 10:00 store time, any
delivery option whose title contains "same-day" is hidden. Before 10:00,
nothing is touched.

Two deliberate refusals to act:

- If same-day is the *only* option in a delivery group, nothing is hidden.
  Shopify rejects a result that leaves a customer with no way to check out, and
  a blocked checkout is worse than a late same-day order.
- If `shop.localTime.timeAfter` is missing — a schema change, a bad deploy —
  it is read as "not past the cutoff". It fails open: the rate keeps showing
  rather than vanishing all day without anyone noticing.

## Deploying it

Requires a Shopify Partner account and the CLI, neither of which was available
where this was written. **None of the steps below have been run.** The logic is
unit-tested; the deploy is not.

```bash
npm i -g @shopify/cli@latest
cd apps/same-day-cutoff
shopify app config link        # creates/links the app, fills client_id
shopify app deploy             # builds the Wasm and uploads the extension
```

Then in Shopify admin:

**Settings → Shipping and delivery → Checkout rules → Add rule**, pick
"Same-day cutoff", and turn it on. A function does nothing until it is
activated there — deploying alone has no effect on checkout.

## Changing the cutoff

The time lives in `src/run.graphql`:

```graphql
timeAfter(time: "10:00:00")
```

It has to be a literal. An input query is static, so it cannot read the time
from a metafield and pass it in. Changing 10:00 to 11:00 means editing that
line and running `shopify app deploy` again.

This is the one place a paid app is genuinely better: Shipy and similar let a
merchant change the cutoff in a settings screen. Worth knowing before choosing
to own this.

## Matching the rate

`CUTOFF_LABEL` in `src/run.js` is `'same-day'`, matched case-insensitively
against the rate's **title**, not its handle. Handles are generated by Shopify
and change when a rate is deleted and recreated — which is what happens
whenever someone edits a shipping zone. The title is what the merchant typed.

So the rate in Shopify must contain "same-day" in its name. The suggested
title, "Same-day delivery — order before 10 AM", matches.

## What this does not do

Hiding the rate after 10:00 is the whole scope. Restricting same-day to paid
orders only is a separate concern and belongs to Payflow, which is already
installed: hide COD when the delivery method is the same-day rate. Payment
methods are chosen after shipping at checkout, so that rule can see which rate
was picked; this function cannot see the payment method and never will.
